## 1. 개요

직원이 사내 시스템의 메뉴를 찾아다니지 않고, Claude에게 말로 요청하면 회사 업무가 처리된다. HR, 재무, 운영, 세일즈, 공급, 전자결재를 하나의 대화창에서 다룬다.

설계 원칙은 "데이터베이스가 진실의 원천"이다. 모든 숫자는 백엔드 로직이 계산하고, AI는 그 결과를 해석할 뿐 지어내지 않는다. 역할별 권한과 감사 로그가 내장되어 있어, 권한이 없는 요청은 거부되고 모든 조회·결재가 기록된다.

OHMY HOTEL은 OTA·여행사 셀러에게 호텔 인벤토리를 공급하는 B2B 유통(베드뱅크) 사업이다. 데모의 지표와 데이터는 이 사업 구조(셀러 정산, 예약, 취소율, 법인 구조)를 반영한다.

## 2. 아키텍처

요청 경로:

```
사용자 → Claude → OHMY ONE MCP → 인증 → 권한 엔진 → 비즈니스 로직(SQL) → PostgreSQL(RLS) → 감사 로그
```

| 계층 | 역할 |
|---|---|
| Claude | 자연어 의도 파악, 업무 액션 선택 |
| OHMY ONE MCP | 이름 있는 업무 액션만 노출 (원시 SQL 도구 없음) |
| 권한 엔진 | 역할·범위 기반 접근 통제, 거부 시 감사 기록 |
| 비즈니스 로직 | 결정론적 계산 (잔여 연차, 정산, 손익 등) |
| PostgreSQL + RLS | 데이터 저장 + 행 수준 보안 (도구 계층을 우회해도 차단) |
| 감사 로그 | 추가 전용(append-only). 민감 작업은 성공·실패 모두 기록 |

구현은 두 층으로 나뉜다.

1. 프로덕션 설계: PostgreSQL 스키마·RLS·업무 함수 마이그레이션(`supabase/`), TypeScript MCP 서버(`mcp-server/`). 실제 DB 연동 전 단계로, 구조와 테스트까지 작성되어 있다.
2. 시연용 데모: 브라우저 안에서 백엔드 로직(권한 엔진·결정론적 계산·감사)을 그대로 재현하는 정적 웹(`web/`). 실제 서버 없이 동작하며 GitHub Pages로 배포된다.

## 3. 사용자 · 역할

7개 역할(페르소나)이 각자 자기 업무만 본다. 역할을 바꾸면 보이는 질문과 접근 권한이 함께 바뀐다.

| 역할 | 주요 권한 | 대표 업무 |
|---|---|---|
| 사원(STAFF) | 본인 연차 조회·신청, 기안 상신 | 셀프서비스 |
| 운영(OPS) | 예약·취소율 조회, 팀 결재 승인 | 예약 운영 |
| 세일즈(SALES/GSM) | 셀러 실적·집중도 조회 | 채널 관리 |
| 공급(SUPPLY/SCM) | 계약유형·마진 조회 | 공급 관리 |
| 재무(FINANCE) | 정산·미수·손익·법인별 마진, 결재 승인 | 재무/회계 |
| 인사(HR) | 전사 연차 분석, 인원 현황, 결재 승인 | 인사 |
| 대표(CEO) | 전사 경영 요약 + 전 영역 조회, 결재 승인 | 경영 |

권한 코드는 영역별로 분리되어 있다. `HR_LEAVE_*`, `FIN_SETTLEMENT_READ`, `FIN_AR_READ`, `FIN_PNL_READ`, `OPS_READ`, `SALES_READ`, `SUPPLY_READ`, `EXEC_READ`, `APPROVAL_APPROVE/REJECT`.

## 4. 기능 모듈

### 4.1 재무 · 회계
- 셀러 정산 요약: 건수, 청구액(GMV), 지급 완료, 미수금, 연체액, 정산주기(통화별)
- 미수금 연령분석: 0–15 / 16–30 / 31–60 / 60일+ 구간, 연체 상위 셀러 팔로업 목록
- 통화별 미수 익스포저: KRW·JPY·USD·CNY·VND, 환리스크 식별
- 법인별 매출(마진)·테이크율
- 손익계산서, 재무상태표(대차 일치 검증)

### 4.2 운영
- 예약 현황: 건수, 룸나잇, GMV, 마진, 테이크율, 취소율, 상태 분포
- 취소율 분석: 채널별 취소율, 상위 채널
- 국가별 예약 분포

### 4.3 세일즈(GSM)
- 셀러 실적 랭킹: GMV·순매출·전월 대비
- 신규 온보딩 셀러와 램프업
- 셀러 집중도: 상위 5개 셀러의 GMV 점유와 집중 리스크

### 4.4 공급(SCM)
- 계약유형별(Exclusive / Dynamic / Shared) 예약·GMV·마진

### 4.5 인사
- 연차 잔여·신청, 팀 연차 현황
- 법인·연도별 연차 사용 분석(소진율)
- 법인별 인원 현황

### 4.6 경영(대표)
- 전사 요약: GMV, 마진, 취소율, 60일+ 연체, 상위 셀러 집중도

각 리포트는 수치만 제시하지 않고, 조치가 필요한 지점(연체 우선 회수, 환헤지 검토, 취소 원인 점검 등)을 한 줄로 덧붙인다.

### 4.7 전자결재(기안)
AI가 기안 양식을 초안으로 채워주고, 담당자가 검토·수정 후 상신하는 2단계 흐름이다.

- 유형: 출장 신청, 경비/지출 결의, 구매 요청, 휴가, 일반 기안
- 작성: 요청 한 줄이면 AI가 지출결의서 같은 문서 양식(기안번호, 기안자, 지급처·계좌, 금액, 지급기한, 내역, 첨부)을 채운다
- 수정: 모든 필드를 편집할 수 있다
- 참조(CC): 여러 명을 선택한다
- 결재선: 결재자를 추가·삭제하거나 바꾼다. 기본 결재선은 금액 기준으로 자동 제안된다
  - 100만원 이하(또는 비용 없음): 팀장
  - 500만원 이하: 팀장 → 재무
  - 500만원 초과: 팀장 → 재무 → 대표
- 상신·승인: [상신하기]로 제출하면 지정한 결재선으로 라우팅되고, 결재자가 순서대로 승인·반려한다. 순서를 건너뛴 승인과 권한 없는 승인은 서버에서 막는다

## 5. 권한 · 보안

- 역할 기반 접근 통제(RBAC)와 범위(본인/팀/전사)로 조회 범위를 제한한다
- 신원은 세션에서 확정한다. 요청에 담긴 ID는 재인가가 필요한 조회 키로만 쓴다
- 다층 방어: 권한 엔진이 각 요청을 막고, RLS가 소유권·범위를 다시 검사한다
- MCP는 이름 있는 업무 액션만 노출한다. 원시 SQL 실행 도구가 없다
- 거부(권한 없음, 순서 위반 등)도 감사 로그에 남는다
- 급여 같은 민감 필드는 열 단위로 보호하고, 권한 있는 함수로만 접근하며 접근 자체가 감사된다

한국어·영어·베트남어·중국어·일본어를 지원한다. 화면 문구, 리포트 라벨, 예시 질문, 거부 메시지가 전환된다. 글로벌 법인(한국·일본·베트남·싱가포르) 대응을 염두에 둔다.

## 7. 기술 스택 · 배포

- 프런트(데모): HTML, CSS, 바닐라 JavaScript (빌드 불필요, 자체 완결)
- 프로덕션 설계: PostgreSQL, Supabase(Auth·RLS), TypeScript MCP 서버
- 배포: GitHub Actions → GitHub Pages (`main` 푸시 시 자동 배포)
- CI: MCP 서버 타입체크·빌드·단위 테스트

## 8. 데이터

데모 수치는 합성(대표 샘플)이며, 실제 사업 구조를 반영한 범위에서 생성한다.

- 법인 4개: 한국, 일본, 베트남, 싱가포르
- 셀러 약 20개(Agoda, Trip.com, Dida, Traveloka, Klook 등 공개 브랜드명 + 합성 수치)
- 직원 약 50명, 회계연도 3개년
- 실제 정산·예약 금액 같은 기밀 수치는 공개 페이지에 넣지 않는다

---

## 9. 범위와 한계

- 워크샵 시연용 프로토타입이다. 프로덕션 배포본이 아니다
- 데모는 브라우저에서 백엔드를 재현한다. 실제 DB·MCP 연동은 다음 단계다
- PostgreSQL 스키마·RLS·MCP 서버는 설계·작성되어 있으나, 라이브 DB 대상 종단 실행 검증과 프로덕션 보안 검토는 아직이다
- "프로덕션 준비 완료"로 보지 않는다
